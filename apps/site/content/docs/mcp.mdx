## Install

```bash
astrograph install                                   # every host, global config; confirms the plan first
astrograph install --target claude --location local  # one host, this project only (.mcp.json)
astrograph install --yes                             # skip the confirmation
```

This writes an MCP server entry and links the Astrograph skill (guidance on when to use which
tool) into each host. `astrograph uninstall` removes both.

To configure a host by hand:

```json
{ "mcpServers": { "astrograph": { "command": "astrograph", "args": ["serve", "--mcp"] } } }
```

## Tools

| Tool | Use it for |
|---|---|
| `astrograph_context` | "How does X work?" — ranked symbols with callers, callees and source. |
| `astrograph_search` | Finding a symbol by (part of) its name. |
| `astrograph_node` | One symbol's details and, optionally, its source. |
| `astrograph_callers` | Who calls, instantiates, extends or renders a symbol. |
| `astrograph_callees` | What a symbol calls. |
| `astrograph_impact` | What may break before editing. |
| `astrograph_trace` | How one symbol reaches another. |
| `astrograph_explore` | Source for several names at once, grouped by file. |
| `astrograph_files` | Which files are indexed. |
| `astrograph_status` | Index health. |

Every tool accepts an optional `projectPath`; by default the server uses the directory the host
launched it in. Before each call the server re-syncs changed files, so results always match the
working tree. Each answer ends with a one-line banner showing the index size and last sync.

## Reading results

References are `exact` unless tagged. `[inferred]` means the receiver's type was not known and
the target was matched by a unique method name; `[external]` targets are in a library or the
runtime. If a project has no `.astrograph/` index, tools say so and the agent should offer to run
`astrograph init`.
