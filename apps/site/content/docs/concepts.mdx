## Symbols

Top-level declarations and class/interface members:

- **TypeScript / JavaScript**: classes, interfaces, functions, methods, fields, top-level
  constants and variables, type aliases, enums. Qualified as `Class.member`.
- **PHP**: classes, interfaces, traits, enums, functions, methods, properties, constants.
  Qualified with their namespace: `App\Models\User::save`.

Code nested inside a function is not a symbol; what it calls is attributed to the enclosing symbol.

## References

A reference is a `call`, `new`, `extends`, `implements` or `render` (a JSX element) from one
symbol (or file-level code) to a name. The linking pass decides what that name points to:

| Resolution | Meaning |
|---|---|
| `exact` | Proven through a binding: a local declaration, an import, a namespace, `this`, or a declared type. |
| `inferred` | The receiver's type is unknown, but exactly one project method has that name. |
| `ambiguous` | The receiver's type is unknown and several project methods share the name. |
| `external` | The target is outside the project: a package, a PHP class that is not indexed, a runtime global or builtin. |
| `unresolved` | None of the above. |

## Where types come from

There is no compiler. Types come from what the file says:

- **TS/JS**: annotations (`x: Foo`), `new Foo()`, typed class fields, constructor parameter
  properties, and declared return types (`const x = make()` where `make(): Foo`; `Promise<Foo>`
  unwraps to `Foo`). Members are looked up through the class hierarchy.
- **PHP**: typed parameters and properties, promoted constructor parameters, constructor
  assignments from typed parameters (`$this->repo = $repo`), `@var` docblocks, `new` and `catch`.

Imports resolve through relative paths, re-export barrels, `tsconfig`/`jsconfig` `paths` and
`baseUrl`, workspace packages, and `require`. PHP names resolve through the file's namespace and
`use` imports (including grouped and `use function`).

## Freshness

Files whose size and modification time did not change are not read. Changed files are hashed,
and only real content changes are re-parsed. Query commands and MCP tools re-sync before
answering. The index is a cache: deleting `.astrograph/graph.db` (or `astrograph index --force`)
is always safe.
