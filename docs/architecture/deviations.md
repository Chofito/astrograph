## Entry format

New entries must include user impact in the prose surrounding the table when the impact is not self-evident, a concrete correction rather than “refactor”, and verification at the same scope as the claim.

## Closure evidence

A row moves to `closed` only when all four are true, and the fourth is not something an agent can supply:

1. The corrected behavior is described concretely, not as “refactored”.
2. The `Evidence` column names the source that changed.
3. The `Required verification` column names the command that proves it.
4. **A user ran that command and reported the result.** An implementation agent must not run the suite, so a row it touches stops at `implemented, awaiting verification`.

Statuses: `open` → `implemented, awaiting verification` → `closed`. A row that skips the middle state is a claim without evidence.
