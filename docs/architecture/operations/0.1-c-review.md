## Round 2 findings and their disposition

Four audits: the oracle's transformations, assertion strength in the JS/TS and PHP fixtures, the
disabled-backend ownership gap, and harness/matrix/governance over-claiming. Two audits
independently found the same non-total edge order, which is why it is treated as confirmed rather
than as one model's opinion.

### Product defects found by building the oracle

| # | Severity | Defect | Fix |
|---|---|---|---|
| R2-1 | **P1** | **A disabled backend left no evidence.** The scanner's extensions came from `registry.allExtensions()`, which omits a disabled backend, so no `.php` path was scanned; membership classified the persisted path `out_of_scope` rather than `backend_disabled`, and `out_of_scope` is not recordable. Rows were deleted and **every query answered `partial: false`** over a project half of which was unindexed. `classifyPath` and `eligibilityEvidence` had implemented the honest path all along; nothing could reach it. | `openProject` builds the scanner from every shipped backend's extensions, enabled or not. Parsing is unchanged — such a file is recorded with zero nodes and reaches no parser. |
| R2-2 | **P1** | **The harness was not hermetic, and it made a wrong answer look right.** `ts.createProgram` had no `types`/`typeRoots`, so TypeScript resolved automatic `@types` from the *process* working directory — this repository — pulling `bun-types` and `@types/bun` into every fixture. `import { join } from "node:path"` in a dependency-less project came back `external`/`high` instead of `unresolved`/`low`, so a fixture asserting that an unprovable target stays unproven passed because the harness had made it provable, and the goldens encoded this checkout's installed types. | Every temporary root gets `HERMETIC_TSCONFIG` (`types: []`, `typeRoots: []`). Module resolution is untouched, so a package installed inside a fixture's own root still resolves. |

### Oracle defects

| # | Severity | Defect | Fix |
|---|---|---|---|
| R2-3 | **P1** | `normalizePath` trimmed at the first `/node_modules/` *before* removing the root, so `<root>/packages/a/node_modules/x` and `<root>/packages/b/node_modules/x` — two distinct declarations in a monorepo — normalized to one path. | Root removal runs first; the `node_modules` fallback applies only to a path still absolute afterwards, i.e. genuinely outside the project. |
| R2-4 | **P1** | `stripRoot` was an unanchored `replaceAll` over free text. With a root of `/tmp/ag`, `"in /tmp/agent/x.ts"` became `"in ent/x.ts"` — byte-identical to a genuinely different diagnostic. | The bare-root replacement is anchored to a path boundary, so a sibling directory survives while `<root>: reason` is still stripped. |
| R2-5 | **P1** | `compareEdges` claimed to be a total order and was not: `metadata` is `retained` but absent from the comparator, so two `ambiguous` edges differing only in their candidates were tied and ordered by SQLite row order. | Canonicalized `metadata` is the final key. |
| R2-6 | **P2, rejected** | `omitUndefined` recursing into `metadata` was reported as destructive: `{candidate: undefined, count: 1}` and `{count: 1}` compare equal. | **Not changed.** `metadata` is persisted as JSON and `JSON.stringify` omits `undefined` object values, so SQLite cannot hold that difference; preserving it would make an in-memory graph diverge from the identical graph read back out. The rule is now stated in the module: this oracle compares *persisted* meaning, and a distinction SQLite cannot store is not a distinction. A meaningful absence must be `null`, which is preserved. |

Each of R2-3 through R2-6 has a regression test in `normalize.test.ts` built from the audit's own
counterexample.

## Residual risks

1. **The goldens were recorded by the implementing agent.** Their invariants are asserted
   independently of the JSON, but no human has read every recorded `graph.json` and
   `envelopes.json`. Round 4 added two more (`php-grouped-use-mixed`, `failure-grammar-missing`)
   that the owner must review as persisted-truth diffs. The per-fixture invariant tests exist
   precisely so that review can be sampled rather than exhaustive; the review expectations in
   [Testing and evaluation](testing-and-evaluation.md#review-expectations) say what to look for.
2. **Finding B (`DEV-009`) is an unfixed product gap**, pinned by a golden. Round 4 also pinned
   `DEV-010` (mixed grouped-use) the same way; neither is repaired. Finding A's deletion is
   fixed (R2-1). Its *reason* residue — `coverage_incomplete` rather than a capability limit —
   is accepted by the owner as `DEV-004`/`NEW-002` and does not block 0.1-C.
3. **Runtime.** The pipeline suite adds roughly 35 seconds on an unloaded machine, and about four
   times that under contention. The explicit timeouts are generous rather than tight.
4. **No real-repository evidence.** `digest()` exists for the corpus that cannot be committed, and
   nothing has used it yet. That path belongs to `DEV-009`'s certification scenario and `NEW-008`.
5. **`bun run check` is red at the baseline** (finding E), so it cannot serve as a gate for this
   stage until those 22 pre-existing findings are dispositioned.
