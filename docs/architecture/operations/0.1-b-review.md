## Findings

No P0 or P1 findings survived the audit. Three issues were found and fixed inside the stage rather
than deferred:

1. **Two capability evaluators** (AG-206). The old per-node `capabilityNotes` consulted whichever
   backend claimed the node's language, which answered the *outgoing* question even for reverse
   lookups. Deleted; domain-directed evaluation is the only path.
2. **CLI formatters inferring behavior from prose.** `callers`, `callees` and `impact` detected a
   capability gap with `note.includes("produces no")`. They now read
   `reason.kind === "capability_unsupported"`.
3. **`loadProject` ran before Pass A** (AG-205). A backend built its project view from the previous
   pass's persisted rows; PHP only worked because it builds its name index lazily. `beginPass` was
   split so the ordering is explicit.

## Deliberate behavior changes

Both are correctness fixes under [contracts §12.4](../../contracts.md#124-compatibility-rules), and
both are in `CHANGELOG.md`:

- **An unproven call no longer resolves when a same-named declaration appears.** Adding `laterFn`
  in an unimported module leaves `laterFn()` `unresolved`, because nothing proves the connection.
  Edges that previously read `resolved` may now correctly read `unresolved`.
- **`partial` is true more often on global questions.** A `resolved` file with a coverage gap, or a
  backend that cannot emit the required edge kind, now makes a global answer partial. A genuinely
  local answer became *less* partial in exchange.

## Exit gate

Unmet until the owner reports results. An implementation agent must not run the suite, so it cannot
supply this evidence.

- [ ] `bun test` — run and reported by the owner
- [ ] `bun run typecheck` — run and reported by the owner
- [ ] `bun run check` — run and reported by the owner
- [ ] `bun run docs:check` — run and reported by the owner
- [ ] `bun run build` plus binary smoke — run and reported by the owner
- [ ] P0/P1 findings resolved or explicitly accepted by the owner
- [ ] The eight `implemented, awaiting verification` deviation rows moved to `closed`, each citing
      the command and result

Only then is 0.1-B closed and 0.1-C free to build the exhaustive production oracle on top of
`normalizeIndex()`.
