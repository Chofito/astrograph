## Findings closed by AG-209

Five defects the first audit did not reach, all found by re-reading the code against the contracts
rather than by running anything:

1. **A watch event could delete relations instead of demoting them.** `syncFiles` named a file as a
   candidate, `runPass` skipped it because membership now rejected it, and `recordIneligibleFile`
   then deleted its rows directly — so foreign keys cascaded the incoming relations away. Losing
   eligibility is now a retirement on every route, and evidence is written only after it.
2. **A successful `trace` hid the destination's unresolved callees.** Evidence came from the
   resolved path alone, while the payload projection dropped target-null edges. The destination's
   relations are now read once, collected before filtering, and merged without double-counting.
3. **A failed `trace` could not see its own blockers.** `blockerEvidence` walked `traverseGraph`,
   which discards a target-null edge before recording a visit — structurally unable to observe the
   hop that blocked the path. A focused `collectPathEvidence` primitive replaces it, and exhausted
   is now distinguished from truncated.
4. **A demoted edge could present a node id as a name.** Retirement filled `targetName` from
   `edge.target`, a content hash. The retired node's textual identity is captured before deletion.
5. **`openProject` leaked its SQLite handle** when migrations, registry construction or grammar
   loading threw after the database was opened.

## Findings closed by AG-208

No P0 or P1 findings survived the first audit. Three issues were found and fixed inside the stage
rather than deferred:

1. **Two capability evaluators** (AG-206). The old per-node `capabilityNotes` consulted whichever
   backend claimed the node's language, which answered the *outgoing* question even for reverse
   lookups. Deleted; domain-directed evaluation is the only path.
2. **CLI formatters inferring behavior from prose.** `callers`, `callees` and `impact` detected a
   capability gap with `note.includes("produces no")`. They now read
   `reason.kind === "capability_unsupported"`.
3. **`loadProject` ran before Pass A** (AG-205). A backend built its project view from the previous
   pass's persisted rows; PHP only worked because it builds its name index lazily. `beginPass` was
   split so the ordering is explicit.

## Deliberate behavior changes

Both are correctness fixes under [contracts §12.4](../../contracts.md#124-compatibility-rules), and
both are in `CHANGELOG.md`:

- **An unproven call no longer resolves when a same-named declaration appears.** Adding `laterFn`
  in an unimported module leaves `laterFn()` `unresolved`, because nothing proves the connection.
  Edges that previously read `resolved` may now correctly read `unresolved`.
- **`partial` is true more often on global questions.** A `resolved` file with a coverage gap, or a
  backend that cannot emit the required edge kind, now makes a global answer partial. A genuinely
  local answer became *less* partial in exchange.

supply this evidence.

- [ ] `bun run check` — run and reported by the owner
- [ ] `bun run docs:check` — run and reported by the owner

- [ ] P0/P1 findings resolved or explicitly accepted by the owner
- [ ] The eleven `implemented, awaiting verification` deviation rows moved to `closed`, each citing
      the command and result

`normalizeIndex()`.
